【节点文档】你的节点文档有四段：请求（请求者写，只读）、职责、结构（plan 环节的 next 写分工表，执行环节的 divide 在表后补上派出了谁）、记录。
不带参数看自己；带 id 看别的节点。只能改自己的：responsibility 整段替换，append_record 追加一条记录；没传的段保留。
brief 把本次工作的短名 name 和一句话目标 description 一起保存；首次理解任务时填写，目标明显改变时更新。它不改请求原文。
prediction 按需保存某一环取得的认识：phase 用 orient、plan，insight 写简短结论与仍待判断的问题。它和记录一起保存；读过提示页只是知道要想什么，交接的是你实际想清了什么。
inquiry为一段调查留下局部预测：purpose 说明为了哪个判断弄清什么，expectation 写预计取得什么认识、到哪里就够。它支持围绕同一问题连续读取、查询和整理资料，临时采集文件先放在临时目录（$TMPDIR）；取得信息后回到当前环判断。同一目的的一批操作共用这份预测。
醒来时按文档重建；工作中 context 太大时，保留最新文档、历史续工摘要和最近工作片段。
