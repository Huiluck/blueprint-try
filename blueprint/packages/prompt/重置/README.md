# 重置：节点读的文字

这份是给人看的文件表，节点不读。写的是 2026-10-24 夜第三版以后的样子（`草稿/十步重置/设计-第三版.md` 第八节、`草稿/十步重置/A交付说明-第三版.md` 第一、五节）：每份文字做什么、什么时候出现在节点眼前。系统设计见《图景》，程序怎么拼见《协议》。

标「第三版新增」「第三版改写」的，是这一版动过的；文字和程序都还没真跑，内容以文件本身为准。第三版前的这份文件表在 `回收站/第三版-2026-10-24/重置README-第三版前.md`，十步重置前的在 `回收站/十步重置-2026-10-24/重置README-重置前.md`。

## 什么时候出现在眼前

- **helm、dock 的稳定开头（系统提示）：** `canon.md` → `shells/公共前缀.md` → `shells/使用情境.md` → `节点/<helm 或 dock>.md` → 节点前缀（身份、节点文档入口、产物空间、请求；有台的节点，产物空间就是它的台目录；总 dock 是整份成品）。每一步都在，逐字不变。总图景只在 helm 的运行背景里。
- **每进入一个环节，接在对话末尾：** 这次发生了什么（叫醒话、纸条、用户的话）→ `开头.md`（职责、欠着的求助、项目经验的标题和入口）、组织情境、任务表（`节点总表.md` 做抬头；helm 看整张，dock 看自己这条线，上级是 dock 的再带兄弟那一层）→ 「【环节：x】」与那一环节的页，单独一条放在最后。helm 的页在 `阶段/helm/`，执行节点的页在 `阶段/`，reply 共用。dock 的 plan 页后面接 `分工表.md`，开了外部 agent 的再接 agent 模式那段；dock 的 execute 页后面接就绪表（它名下登记着的 part 哪些现在能做、哪些在等谁）。和上一个环节同一页、中间没重建、页没改过、就绪表没变，就只接环节名一行。
- **选择机那次调用：** 节点这一步要发的那一份原样，末尾接 `选择机.md`。回答不留在对话里。
- **run：** `节点/run.md` → `shells/公共前缀.md` → `shells/使用情境.md` → 节点前缀（身份、产物空间即它的台、请求；不给节点文档入口）。不读 canon，不过选择机，不插环节页，没有任务表和总图景。
- **交给 Codex／Claude Code 的 run：** 在它的台目录里开工，交给它 `外部run.md` ＋ `外部run技能.md` ＋（按停或重起后 `外部run被打断.md`、并入撞冲突 `外部run冲突.md`）＋ 请求。外部 agent 只当 run。
- **派人时：** `请求/dock请求.md` 或 `请求/run请求.md`（照上级写的 role）填好，写进下级节点文档的请求段，也就是它节点前缀里的请求。
- **工具说明：** `工具/` 下的每一份，在工具表里每一步都带着。
