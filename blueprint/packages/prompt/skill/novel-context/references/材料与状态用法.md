# 材料与状态用法

## 取得章节材料

`context --book <目录>` 默认扫描 `正文/` 的 Markdown 文件。`--chapters <相对目录>` 可换成当前作品目录；按文件名中的 `第12章`、`第十二章` 或 `12_章节名` 排序，无章号的文件列为“未排序”，可用 `--read` 单独读取。

| 参数 | 用途 |
| --- | --- |
| `--chapter 12` | 只取第 12 章之前的结尾；省略则取已发现的末几章 |
| `--character <人名>` | 可重复；从 `人物卡/`、`设定/角色/`、`设定集/人物/` 查找同名 Markdown |
| `--id <状态条目>` | 可重复；只取指定 ID 与上述人物的长篇状态；省略则交回现有全部状态 |
| `--read <路径>` | 可重复；读取当前书目录中的任意指定文本文件 |
| `--tail-chapters 3` | 默认取最近 3 章；按当前问题调整，0 表示不取 |
| `--tail-chars 800` | 每章结尾的字符数；会明确报告前面省略了多少 |
| `--budget 24000` | 交回的材料正文总字符预算；超出部分列在覆盖报告里，可补读原文件 |
| `--state <路径>` | 改用书目录内的状态文件，默认 `创作记录/小说状态.json` |
| `--json` | 输出带路径、原文、截取范围与缺失项的 JSON |

脚本不理解情节，也不从人名推断出场关系。一个人物名找到多个文件时列出候选，使用 `--read` 指定要读的；找不到就报告缺失。指定的文本文件交回全文，只有章节结尾和显式总预算会裁剪；不会把“读了部分”称为“材料齐全”。所有书内路径均限制在 `--book` 内，不跟随指向其他项目的软链接。

## 长篇状态

`state init` 建空白账本；也可 `--input <初始状态.json>` 导入同格式的已整理内容。已有账本不会被初始化覆盖。`state show --json` 读取原始状态；不加 `--json` 则交回分栏的可读文字。全书条目较多时，`state show --character <人名> --id <条目名>` 只交回指定记录、各栏覆盖量与未找到的名字，不把部分结果当原始状态。空白格式见 `assets/长篇状态模板.json`，它是机器数据格式，不要求作者填写表单。

| 栏目 | 最少字段与含义 |
| --- | --- |
| `position` | 当前工作位置；可含 `chapter`（非负整数或 null）、`title`、`scene` |
| `authorFacts` | `{ "id": "事实名", "text": "作者已确定但未必揭露的事实", "source": "依据" }` |
| `characters` | `{ "name": "人物名", "known": ["该人物已知的信息"], "source": "依据" }`；可加位置、目标、资源等字段 |
| `events` | `{ "id": "事件名", "fact": "实际发生了什么", "readerKnowledge": "读者截至此处知道什么", "source": "依据" }` |
| `threads` | `{ "id": "伏笔名", "text": "待兑现的内容", "status": "当前情况", "source": "依据" }` |
| `openQuestions` | `{ "id": "问题名", "text": "尚未确定的问题", "source": "相关材料" }` |

各条目可带其他 JSON 字段，`source` 建议指向章节、设定或作者原话，脚本不替节点验证其语义。ID 用有含义的稳定名称。作者事实不等于读者已知，人物的 `known` 也不由脚本自动推导。

一次变化的格式：

```json
{
  "expectedRevision": 0,
  "position": { "chapter": 1, "scene": "当前场景" },
  "upsert": {
    "characters": [{ "name": "人物名", "known": ["本次已确认的信息"], "source": "正文/本章.md" }],
    "openQuestions": [{ "id": "未定方向", "text": "留给后续判断的事" }]
  },
  "remove": { "openQuestions": ["已解答问题"] }
}
```

`expectedRevision` 取自当前账本；过期时重新读取，再合入自己的变化，避免覆盖其他节点的成果。`upsert` 按 ID 或人物名替换整条记录，未列出的条目保留；更新时保留仍有效的字段。`remove` 只删除明确列出的条目；同一条不能同时替换和删除。`position` 是当前工作位置，可回到旧章改稿，不是创作进度门禁。

脚本一次原子替换一个状态文件。并发写入报“状态正在更新”时，待本次写入结束后重读；异常中断留下写锁时，先确认没有状态写入正在进行，再处理账本旁的 `小说状态.json.写入锁`。它不改正文、不启动服务、不把语义冲突当成写入权限问题。
