# 小说材料与长篇状态

让当前这场戏有可追溯的前文：发生过什么，人物知道什么，读者已经知道什么，还有哪些承诺未兑现？取得足够支持本次写作或审稿的材料就够，脚本返回原文与覆盖范围，取舍由持有书稿 context 的节点判断。

需要 Node 18+，无第三方依赖。下列脚本路径相对于本 skill 目录；在当前项目用脚本绝对路径调用。

```bash
node "<本技能目录>/scripts/小说材料.mjs" context --book "<书目录>" --chapter 12 --character "<人物名>" --read "大纲/<本章细纲>.md" --tail-chapters 3 --tail-chars 800
```

它读取指定人物卡、文件、前面几章的结尾与已有长篇状态。结果列出未找到、无法排序或因篇幅未完整交回的材料，并给出原文件入口；跨卷事实或伏笔出处仍可按问题补读全文。目录与参数见[材料与状态用法](references/材料与状态用法.md)。

需要持续跨章保存故事事实时，使用书目录下的 `创作记录/小说状态.json`。已有设定和正文仍是事实依据；状态是带来源的工作账本，不把计划写成已发生。

```bash
node "<本技能目录>/scripts/小说材料.mjs" state init --book "<书目录>"
node "<本技能目录>/scripts/小说材料.mjs" state show --book "<书目录>"
node "<本技能目录>/scripts/小说材料.mjs" state apply --book "<书目录>" --input "<本次状态变化.json>"
```

状态内容由读过正文的节点提取。作者事实、人物已知和读者已知分开记，未定的放进待决问题；章后更新或改稿后纠正都可以，脚本只核对格式、更新指定条目并避免并发覆盖。正文保存与分工沿当前系统；需要按作者文风改稿时读 `novel-revision`。
