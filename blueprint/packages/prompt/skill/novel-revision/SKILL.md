# 按作者文风修订小说

让文字更合作者意图，并看清改动对故事的影响。当前段落哪里让阅读停滞，哪些表达正在承担人物、情绪或信息揭露的作用？按这次修订范围处理，够解决具体问题就停。

先取得原文与本书文风。需要人物和前文事实时使用已有材料或 `novel-context`；文风、当前请求与参考冲突时，按表达维度取值，当前请求优先，本书明确选择优先于通用参考。用法和修订分寸见[文风与改稿](references/文风与改稿.md)。

下列脚本路径相对于本 skill 目录，在当前项目用绝对路径调用。需要 Node 18+，无第三方依赖。

```bash
node "<本技能目录>/scripts/文风修订.mjs" style --book "<书目录>" --current "<本次请求.md>"
node "<本技能目录>/scripts/文风修订.mjs" inspect --file "<正文.md>"
node "<本技能目录>/scripts/文风修订.mjs" compare --before "<修改前正文.md>" --after "<修改后正文.md>" --preserve "<本次应保留的词或信息片段>"
```

`style` 交回有来源的文风原文；`inspect` 只定位重复候选，是否有问题看本书文风和该句的叙事作用。由读过当前稿件的节点改写，`compare` 再交回改动范围、字数变化与指定片段的保留情况，语义和读感仍需对照原文。

只改表达时，保留仍有用的情节、人物特征和信息边界；作者要调整故事时，按他指定的范围改。候选不是禁用词，不为消除命中去替换作者认可的写法。交回具体改稿与有影响的取舍，长期偏好只记录作者明确声明的内容。
