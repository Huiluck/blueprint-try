# 文风与改稿

## 取得当前生效的文风

`style --book <书目录>` 交回 `设定/文风.md`、`文风卡.md`、`文风.md` 中实际存在的原文。多份并存时保留各自出处，节点根据当前稿件判断；脚本不从文件名推断哪份已经过期。另有材料时可以显式传入：

| 参数 | 内容 |
| --- | --- |
| `--current <文件>` | 本次作者请求，可重复 |
| `--book-style <文件>` | 本书另存的文风原文，可重复 |
| `--author <文件>` | 作者明确声明、且本次适用的长期偏好，可重复 |
| `--reference <文件>` | 本次选定的对标或参考，可重复 |
| `--json` | 带出处与优先级的 JSON |

显式文件参数相对于命令当前目录解析，也接受绝对路径；不会主动查其他作品或长期记忆。只读原文，不要求作者填配置，不从反复改稿推断喜好。

表达选择按维度看：当前请求 ＞ 本书明确文风 ＞ 作者明确且适用的长期偏好 ＞ 选定参考。视角、句长、标点、对话、修辞、叙述者评论和结尾可以各自来自不同层。下层只补上层没有说的维度，同一层的真实冲突才需要澄清。表达自由与故事事实分开：换成限知视角可以暂不写人物不知道的事，不据此补造他的知情经历；修辞偏好也不自动改变情节或揭露时点。

维度较多时，节点可从上述原文提取 `assets/文风取值模板.json` 的结构，再运行：

```bash
node "<本技能目录>/scripts/文风修订.mjs" resolve --input "<本次文风依据.json>"
```

每个层是条目数组，条目至少有 `dimension`、`value`、`source`，可加作者原句 `evidence`。同维度采用最高层的明确选择；同层值不同则列为待定，不自动猜选一个。结果保留被覆盖的参考，便于检查取值依据。这个格式用于节点整理复杂冲突，一句明确的作者偏好可以直接使用。

## 改稿的判断

修订围绕本次真正的问题展开：读者在这里应该得到什么变化，当前文字哪里让它失效？重复可能是空转，也可能在形成回声或人物习惯；解释可能泄露信息，也可能是叙述者刻意的声音。先读上下文，再决定保留、删减或换写。

优先处理能明确指出影响的地方。保留有效句子；要删一段时，检查其中是否还承担因果、伏笔、动作结果或情绪承接。复杂段落需要重写时，以这些功能和作者选择为依据，不把统一句长、标点数量或词表命中率当目标。改后再读与上下场的衔接，以及人物知情范围、动作顺序和情绪的变化。

## 脚本辅助

`inspect --file <正文>` 可传多份文件，交回每份的字符、句长与段长统计，以及带行号、原句的重复候选。句子按句末标点和换行切分，只是字面统计。`--min-repeats 3` 默认同一表达出现 3 次才列出；`--phrases <候选.json>` 可换成本次关注的表达列表，空列表就只检查原句重复。候选来源是 `assets/重复表达候选.json`，它只是定位材料，不是质量规则。发现候选不会修改正文，也不会返回“不合格”。

`compare --before <原稿> --after <改稿>` 交回首尾相同部分之外的改动跨度与节选；多处修改时这个跨度可能包含未改文字。`--preserve <字面片段>` 可重复，逐项统计在两版中的出现次数并提示是否全数消失。它只能验证字面保留，不能证明事实、伏笔或读感保持不变。作者要看完整改稿时交回文件入口，语义判断引用具体位置。
