# 看听

要知道一段录屏或音频里"第几秒发生了什么、哪里不对"，先建一次索引，再按索引问。

## 为什么这样做

- **只看一遍。** 逐帧抽图来看，几张图就占掉一大块 context；换个节点、换个问题，又得从头看。这里把整段看一遍、听一遍，结论写成带时刻的卡片，跟文件指纹绑在一起，存在项目临时目录里。文件没变，谁再来都直接用现成的卡片（第二次不到 1 秒），不用再看图。
- **先粗后细。** 问问题时先读卡片，是文字，便宜；只把最相关的几帧原图附上。要看清一个动作、量准一个时长，才对那一秒"细看"：每秒 12 帧、画面中间放大。越贵的一步，用得越少。
- **用对感官。** 画面交给能看图的模型（DeepSeek），声音交给能听的模型（MiMo），响度、峰值、静音、削波由 ffmpeg 在本地量。"第几秒突然变响"这种事，本地量比模型听更准；"那一声是什么、听着怎么样"，要靠能听的模型。两边一起写进卡片，不再让看不见、听不见的一方拿数字去猜。

## 怎么用

```bash
S="/本skill目录/scripts/看听.py"
python3 "$S" 索引 录屏.mp4                                 # 30 秒的视频约 20 秒；文件没变就直接用现成的
python3 "$S" 问 录屏.mp4 "巨像落地那一下，吼声对上了吗？"
python3 "$S" 细看 录屏.mp4 14.2 "红光从哪一帧开始，持续多久？"
python3 "$S" 帧 录屏.mp4 7                                 # 导出那一刻的原图
python3 "$S" 片段 录屏.mp4 6-9                             # 导出一小段，给人看
```

建索引时会打印时间线。索引目录里还有：

- `时间线.md`：全部卡片，按时刻排好。
- `联系表.jpg`：所有采样帧拼成一张，每格标着时刻。读这一张，就看完了全片。
- `频谱.png`：有声音时才有，横轴是时间。
- `索引.json`：卡片原样，给脚本用。

纯音频文件（wav、mp3、m4a）也能用，只做声音那一半。

## 读结果要知道的

- 一分钟以内的视频，卡片每秒一张，所以时刻和时长只准到约 ±1 秒。要精确到帧，用细看。
- "画面大变"是按像素自动检测的，不一定是切镜头；暗色画面之间的切换常常检测不到。以画面卡片为准。
- 声音卡片写的是"听起来像什么"，模型偶尔会听错或多报。"静音、接近满幅、突然变响"是本地量出来的，可以直接引用。好不好听、合不合意，最后还是要人来听。
- 文件一改，指纹就变，会重新建索引。引用读数时写上指纹，也就是索引目录名，别人就知道是哪一版。
- 画面要 `DEEPSEEK_API_KEY`，声音要 `MIMO_API_KEY`。缺了哪一个，就只做另一半，并在结果里说明。ImageMagick 可选，用来在联系表上标时刻。

## 什么时候用

- **总 dock 看接好的成品录屏。** 建一遍索引，问"哪里断了、声画对不对"，把结论和时刻写进验证。别的节点不必再看这段录屏。
- **做一块的验自己这块。** 比如做音频的，听自己的音乐床有没有爆音、静音，该响的地方响没响；做动画的，看自己那段动作在第几秒起、第几秒落。
