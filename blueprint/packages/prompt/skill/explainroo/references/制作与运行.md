# 制作与运行

## 两份文件协作

`script.md` 是旁白与场景划分，`scenes.js` 是相同场景的绘图与动作。`video.json` 保存尺寸、主题、声音等项目设置。

```markdown
# DNS 如何找到服务器

## request {min=4}
浏览器需要找到服务器的地址。[#lookup] 它向解析器发出查询。

## response {hold=1}
解析器返回地址。[#connect] 浏览器用这个地址建立连接。
```

`##` 后的场景 ID 与绘图场景对应。`[#lookup]` 等标记命名旁白中的时刻，动作通过 `s.mark('lookup')` 对齐；`s.cue('word')` 用于匹配实际朗读词句。`[pause 0.6]` 表示停顿，`{显示词|朗读词}` 用于发音覆盖。具体绘图 API 看官方手册和 `references/toolkit/templates/starter/scenes.js`。中文示例说明写法；不证明上游英语语音流程能处理中文。

示例目录：`how-dns-works` 用移动关系解释查询，`merge-vs-rebase` 用图结构解释变化，`sqlite-demo` 展示代码与数据。可按当前问题挑一个，提取其解释方式与代码结构。

## 创建项目

从项目目录调用本 skill 工具源码的实际路径，创建一个有意义的新目录：

```bash
node /实际技能目录/references/toolkit/bin/explainroo.js init 视频/解析地址 --theme paper --title "解析地址"
```

这会生成项目文件，不需要下载语音模型或启动浏览器。源码要求 Node 20.11 及以上。共用技能目录保留为资料；需要安装依赖时，将工具源码复制到项目自己的工具目录再安装。

## 当前 Blueprint 的制作方式

可以使用项目文件、分镜、绘图资料和解释方法。需要在 App 内预览动画时，把场景做成项目内可运行的 HTML/Canvas；为要检查的时刻提供能冻结画面的入口，再用 `render_page` 和 `read_image` 查看。素材路径及网页模块按项目预览服务运行。

上游完整渲染依赖独立 Chromium 与 Playwright，现版 Blueprint 未接入这种控制方式。不能把内置网页截图当作上游逐帧渲染器，也不能靠命令升权补齐集成。在当前 App 中，依照可用媒体能力制作配音、使用已有视频制作工具导出，或明确交回可预览的场景与尚未导出状态。

## 已具备上游运行环境时

在支持该渲染方式的环境中，项目内工具安装 `package-lock.json` 锁定的依赖，并用 `doctor` 确认实际条件；模型缓存用 `EXPLAINROO_CACHE` 指向项目目录。语音模型首次使用会下载数百 MB。

上游流程是 `voice` 生成旁白及时间，`check` 查布局和时间问题，`still` / `sheet` 提供画面，`render --draft` 试片，`render` 导出，`verify` 检查文件。命令参数与输出以官方手册和实际运行结果为准。

此快照的 Kokoro 声音和 Whisper 对齐配置面向英语，中文任务需要支持中文的配音与时间对齐方案。图片可用项目已有图片能力生成后作为素材；上游自带 OpenRouter 图片命令是另一种可选实现。
