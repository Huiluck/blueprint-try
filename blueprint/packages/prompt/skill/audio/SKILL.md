# 声音

## 先找现成的

免费曲库和音效库里多是真乐团、真合唱、真录音。从零用程序合成，要先写振荡器、共振峰、混响，一首配乐常要上百步，出来仍偏电子音；音效也一样。所以先找：

- 用 resource-reuse 技能的声音搜索：候选做成一张试听页，不下载就能挑；选定了再取，来源由脚本记下。渠道见它的「动作、动画、音乐、音效与视频」。
- 找到的不完全对，就剪、叠、变调来凑；合成只补找不到的那一层（比如一个特定音高的持续音），不从零写整首。
- 听不到声音时，按时长、标签、简介挑；背景音乐、招牌音这类听感定方向的，试听页交给能听的人或模型。

## 做成能用的

```bash
# 剪一段、淡入淡出、统一到 -16 LUFS，出 16 位 WAV（剪在滤镜里做，淡出的秒数才按剪出来的那段算）
ffmpeg -y -i 原.mp3 -af "atrim=start=12:duration=46,asetpts=PTS-STARTPTS,afade=t=in:d=0.05,afade=t=out:st=45.5:d=0.5,loudnorm=I=-16:TP=-1.5:LRA=11" -ar 48000 -c:a pcm_s16le 出.wav
# 音效：去掉开头的静音，再统一峰值（体检 --json 里「到-1真峰要加」是几，就加几 dB）
ffmpeg -y -i 砸.wav -af "silenceremove=start_periods=1:start_threshold=-60dB,volume=2.2dB" -c:a pcm_s16le 砸_出.wav
# 无缝循环：截一段，首尾交叉淡化；长度落在小节线上（秒＝小节数×每小节拍数×60÷BPM）
python3 "/本skill目录/scripts/做循环.py" 原.mp3 战斗_loop.wav --起 8 --长 46.45 --交叉 0.5
```

音效做成按事件触发的短件：一个动作拆成起势、冲击、碎屑几条，开头不留静音。什么时候响，由动画事件触发，接线归整合的人；不把接触时刻烤进一条长文件，动画一改时长，长文件就得重做。

## 放进 Godot（4.7.2 实测）

- 默认导入是有损的 QOA（`compress/mode=2`）；音乐和要保住低频、峰值的音效改成 0。
- 循环文件 `edit/loop_mode=2`，导入后是正向循环，循环终点自动取最后一个样点。
- ffmpeg 写的 24 位 WAV 是扩展头，导入报 not PCM；交给引擎的用 `-c:a pcm_s16le`。
- `.import` 跟着声音文件一起交；删了重导，就回到默认的有损。
- `--headless` 时音频驱动是 Dummy，引擎里听不到。

## 量一次

```bash
python3 "/本skill目录/scripts/声音体检.py" audio/                  # 一张表
python3 "/本skill目录/scripts/声音体检.py" 战斗_loop.wav --循环 --json
```

一个文件不到一秒，改了再跑一次，不另写测量脚本。表里有格式、时长、峰值与真峰、响度、首尾静音、循环接缝；「要看的」一列只列可能出问题的：真峰高过 -1、削波、直流、短件开头的静音、循环接缝的咔哒和电平跳、Godot 导入会失败或导成有损。在 Godot 工程里，带 `edit/loop_mode=2` 的文件自动当循环量。

这些数字说的是能不能用，不是好不好听。好不好听：项目接了能听的模型，用 av-review 听一遍；没有，写进 verify 交出去（行首「人：」），不拿响度、频谱去逼近听感。
