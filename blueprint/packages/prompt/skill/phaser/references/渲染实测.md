# Phaser 4.2.1 渲染：实测走得通的路与会静默失败的坑

来自一次真机验证（Chrome 155、Apple M1 真 GPU、headless=new），每条都用探针跑过。这里没写的，就是还没测过，用之前自己先试。

## 走得通

- **加色光效合批**：同一图集、同一 blendMode（`ADD`）、在显示列表里连续摆放，200 个渐变面片只要 3 次绘制调用。三条缺一条，合批就断。
- **内部分辨率**：game config 的 `width/height` 设成显示尺寸 × 0.85（1280×720 → 1088×612），canvas 的 CSS 尺寸设回显示尺寸，浏览器负责放大，不需要额外的 pass。
- **构图不随清晰度变**：构图空间固定在显示尺寸，相机 `zoom = 后备缓冲宽 / 显示宽`、`setOrigin(0,0)`；降清晰度只改后备缓冲，不会把画面裁掉。
- **视差**：`scrollFactor` 写在每个 GameObject 上，相机只做平移。**Container 不吃 `scrollFactor`**，放进容器的层不会动。像素级核对过：相机 `scrollX=200` 时，0.02 / 1.0 / 1.35 三层落点与 `640 − 200×视差` 一致。
- **可复现**：固定 60Hz 步长的累加器加带种子的随机数（mulberry32），同种子两次跑 1500 步结果一致，帧长抖动不改变模拟步数。截图、录屏要定格时靠它。
- **GPU 计时**：Phaser 4.2.1 建的是 **WebGL1** 上下文，用 `EXT_disjoint_timer_query`；`..._webgl2` 拿不到。

## 相机滤镜的参数（静默失败最多的地方）

| 滤镜 | 实测 |
| --- | --- |
| `addGlow` | 可用，就是 bloom。**只认位置参数** `addGlow(亮部色, 外强度, 内强度, scale, knockout, quality, distance)`；传配置对象会被忽略，按默认值跑 |
| `addVignette` | 可用。构造参数无效，建完再改 `radius/strength/x/y`；**`color` 不能赋数字**，赋了会把整屏压暗 |
| `addBlur` | 可用，位置参数 `addBlur(quality, 半径x, 半径y, strength)` |
| `addThreshold` | 可用，`setEdge(edge1, edge2)`、`setInvert()` |
| `addColorMatrix` | **没有效果**，调色要靠生成时的颜色加一层色偏叠加 |
| 颗粒、色差 | 没有同名滤镜：颗粒用噪声贴图叠加层；色差只能近似（亮部边缘红蓝各错开几像素） |

`addBarrel`、`addPixelate`、`addBokeh`、`addTiltShift` 等也在运行时导出里，没有逐个试过。

## 走不通：自写离屏多 pass

想把场景先画进一张自己控制的纹理再做全屏后处理，在 4.2.1 上每条路都试过了，都不行：

- `game.textures.addRenderTexture(key,w,h)` 抛错（`texImage2D: Overload resolution failed`）。
- `game.textures.addDynamicTexture(key,w,h)` 建得出来，但没有可采样的纹理句柄。
- `scene.add.renderTexture(x,y,w,h)` 的 `fill()/draw()` 不报错，内容却没有落进去。
- `gl.copyTexImage2D/copyTexSubImage2D` 读默认帧缓冲一律 `GL_INVALID_OPERATION`；`readPixels` 再上传每帧约 9ms，撑不住 60fps。
- `renderer.captureNextFrame/startCapture/onCapture` 是空实现；从画布直接取图会形成反馈环，几帧后整屏变黑。

所以真全屏色差、逐像素分通道这类效果，这个版本做不了，要么用上面的近似，要么换渲染路线。

## 加载外部素材时

- **`PRE_RENDER` 事件会早于 `create()` 触发。** 有贴图要加载时，头几帧场景对象还没建，回调里一访问就抛异常，整个渲染循环断掉，画面全黑却没有报错。回调开头先判断对象是否已建。
- **竖向渐变的雾带别用 `tileSprite` 铺**，会在竖向重复成几条横带；用 `add.image(...).setDisplaySize(宽, 高)` 整张拉伸。反过来，很宽的剪影层要用平铺贴片。

## 测帧时间的口径

- 锁 60Hz 时帧间隔 p95 会因 vsync 抖动略高于 16.7ms（实测 17.1ms），同时段长帧为 0，这不是掉帧。判断够不够快，看 >33ms 的长帧数和关掉 vsync 的吞吐（实测约 199fps）。
- headless=new 的截图视口比 `--window-size` 小一截（1280×720 只拍到 1280×577）。要完整一屏，用 CDP 的 `Emulation.setDeviceMetricsOverride(1280, 720, 1)`。
