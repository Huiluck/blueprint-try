# 设计判断

先理解使用者在这里要取得什么。操作界面需要稳定、容易扫描的结构；阅读内容需要舒适的节奏；介绍和展示可以用构图表达性格。同一种视觉处理，在不同用途里可能产生不同效果。

## 从实际画面找到主要问题

把细节暂时模糊，看看最重要的元素是否先被看见，次要元素和主要分组能否辨认。再沿使用者的任务路径检查：在哪里寻找信息、做决定、行动、等待或恢复。

相关内容之间的距离是否更近？容器是在表达关系，还是掩盖分组不清？信息密度是否适合使用频率与决策难度？窄屏、长标题、缺失内容、放大文字时，结构还能表达原来的优先级吗？

问题描述落在可观察的结果上：哪个内容或操作，在什么情境下难以发现、理解或使用；什么变化能改善它。功能阻塞、误导和无法使用的状态，通常比装饰细节更影响作品。

## 形成一致的方向

方向来自内容、受众、产品语气和现有约定。选择少量能支撑这个方向的空间关系、字体角色、颜色角色和交互表达。已有项目先理解其设计系统与邻近页面，再判断局部失误还是系统本身需要改变。

布局让内容关系可见：用接近表达归属，用分离表达差异，用尺寸、位置和留白表达优先级。重复支持辨认；内容和重要性改变时，布局才需要改变。卡片、渐变或不对称都要有承担的作用。

评审后优先处理最妨碍当前目标的问题，在整条任务路径上检查相同问题是否存在。一次修改应让具体效果更清楚；不要为了变化本身替换用户已经选择的视觉身份。

## 效果的依据

实际内容和渲染画面能说明层级、节奏、溢出与可读性；代码和尺寸能解释原因；真实交互才能说明操作路径。依据不足的部分保留为待确认判断。机械检查通过，只说明它检查到的缺陷没有出现。
